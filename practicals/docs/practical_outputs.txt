===== Note on output ordering =====
When stdout is a pipe or a file, glibc buffers it fully instead of line-by-line.
fork() duplicates that unflushed buffer, so lines printed before fork() can appear
twice. Running the programs directly on a terminal (line-buffered), or adding
fflush(stdout) before fork(), removes the duplication. This does not change the
PID/PPID values being demonstrated.

===== Practical 9a : copy_lowlevel vs copy_stdio (100 MB, both -O2) =====
$ ./copy_lowlevel input.dat output_low.dat
Source file size: 104857600 bytes
File copied successfully.
$ ./copy_stdio input.dat output_stdio.dat
Source file size: 104857600 bytes
File copied successfully.

$ sha256sum input.dat output_low.dat output_stdio.dat
4e861ac53747ec4720a733d525fdb0c9c438708347eb21c41297c0cdb40360bf  input.dat
4e861ac53747ec4720a733d525fdb0c9c438708347eb21c41297c0cdb40360bf  output_low.dat
4e861ac53747ec4720a733d525fdb0c9c438708347eb21c41297c0cdb40360bf  output_stdio.dat
(cmp reported no differences for either copy)

Timing - 6 alternating runs each, first discarded as warm-up:
  copy_lowlevel  106 104 107 103 106 ms   median 106 ms   ~943 MB/s
  copy_stdio     122 121 132 119 120 ms   median 121 ms   ~826 MB/s
  low-level is ~14% faster

System calls (strace -c):
  copy_lowlevel  12802 read  + 12801 write = 25603
  copy_stdio     12802 read  + 25600 write = 38402
Write sizes on a 10 MB file:
  copy_lowlevel  1280 writes of 8192 bytes
  copy_stdio     2558 writes of 4096 bytes (+1 of 8192)
Reason: glibc gives the stream a 4096-byte buffer, so each 8192-byte fwrite()
is split into two 4 KB writes - an extra memcpy and twice the syscalls, because
the program already buffers at 8 KB itself.
