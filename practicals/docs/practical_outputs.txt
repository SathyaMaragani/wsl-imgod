===== Practical 4b : zombie_process =====
Parent Process: PID = 493
Child Process: PID = 495
Child Process: Exiting...
Parent Process: Child PID = 495

Child has terminated.
Parent has NOT called wait() yet.
Therefore, the child becomes a ZOMBIE.

>>> Check the process table NOW.
>>> You have 20 seconds to run: ps -el

--- process table during the 20 s window ---
$ ps -el
F S   UID     PID    PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
0 S  1000     493     334  0  80   0 -   691 hrtime pts/0    00:00:00 zombie_process
1 Z  1000     495     493  0  80   0 -     0 -      pts/0    00:00:00 zombie_process

$ ps -o pid,ppid,stat,cmd -e
    493     334 S+   ./zombie_process
    495     493 Z+   [zombie_process] <defunct>

State Z and the <defunct> tag confirm the zombie. SZ is 0: the address space is
already gone, only the process-table entry (exit status) remains.

--- after the parent calls wait() ---
Parent: Calling wait() now...
Parent: Child exited normally.
Parent: Child exit status = 10
Parent: Child has been reaped.
Parent: Zombie process eliminated.

$ ps -o pid,ppid,stat,cmd -e | grep zombie_process
(no entries - the zombie has been removed from the process table)

===== Note on output ordering =====
When stdout is a pipe or a file, glibc buffers it fully instead of line-by-line.
fork() duplicates that unflushed buffer, so lines printed before fork() can appear
twice. Running the programs directly on a terminal (line-buffered), or adding
fflush(stdout) before fork(), removes the duplication. This does not change the
PID/PPID values being demonstrated.
